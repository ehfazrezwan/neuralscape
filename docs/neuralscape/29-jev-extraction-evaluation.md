# Jev source-selection extraction: implementation and evaluation

Evaluated 2026-09-21 on `codex/hybrid-system-one`, based on `dev` at
`c4b83ff8af2ad18cfc2bd81b4d4eec2ff857de39`. Not deployed; all hybrid flags remain
off by default. This extends [the initial hybrid evaluation](28-hybrid-system-one-evaluation.md).

**Latest follow-up:** category distributions are now persisted as soft relevance
metadata, with bounded extraction waits and separate uncertainty telemetry.
See [the probability/latency follow-up](#probability-and-latency-follow-up) below.
The original evaluation is retained for comparison, not overwritten.

## Result

The redesign removes the generative extraction call for confidently selected
source facts and confidently rejected non-facts. It reduced median extraction
latency and listed API cost in both synthetic sets, but **increased tail latency**.
The downstream graph/vector pilot preserved all 21 acceptance checks and reduced
generation cost; total write time was essentially unchanged. This is evidence
for an opt-in trial, not a production-wide speed or accuracy guarantee.

| Measure | Existing Gemini extractor | Jev-first + Gemini fallback |
|---|---:|---:|
| Development set: 20 inputs × 3, median | 716 ms | 539 ms (25% lower) |
| Development set p95 | 809 ms | 1,303 ms (61% higher) |
| Development set listed API cost | $0.012297 | $0.007075 (42% lower) |
| Development strict rubric passes | 42/60 | 54/60 |
| Held-out set: 12 inputs × 3, median | 724 ms | 396 ms (45% lower) |
| Held-out set p95 | 793 ms | 1,449 ms (83% higher) |
| Held-out set listed API cost | $0.007290 | $0.003258 (55% lower) |
| Held-out strict rubric passes | 24/36 | 33/36 |
| Calls avoided: generative extraction | — | 38/60 development; 28/36 held-out |

Provider calls are not the same as avoided Gemini calls: development hybrid made
48 Jev + 22 Gemini calls; held-out hybrid made 33 Jev + 8 Gemini calls. Fallback
cost is included. These are small, sequential, repeated synthetic corpora, not
96 independent production examples. No confidence intervals or concurrency/load
claims. Network variability and concurrent local validation can affect timing.

The first Jev request includes lazy tokenizer/client initialization: 2.65 seconds
in the scoped development run and 1.67 seconds held-out. The initial exploratory
run had a 17.13-second first request. No samples were removed from reported
percentiles; warm medians should not be interpreted as cold-start guarantees.

## What changed

`jev_extraction.py` uses the existing spaCy dependency's blank English tokenizer
and sentencizer, without model weights or downloads. It constructs exact source
offsets and batches three questions per span: retain as durable memory, safe as
one standalone verbatim fact, and canonical category. Bucket descriptions and
contrastive routing policy are shared once per request, not repeated per span.
The existing Jev adapter provides strict response validation, bounded input,
timeouts and content-free telemetry. Default confidence remains 0.9.

The output text is reconstructed from the source, never generated by Jev.
Exact duplicate category/text pairs are removed. There is an 8 KB source and
16-sentence budget; exceeding either falls back without truncating evidence.
One uncertain positive makes the entire window fall back, with no partial
facts written first. `None` means fallback; an accepted empty list means no
durable facts and must not trigger generation.

Both `extract_facts_only` and conversation extraction use the new lane. Custom
domain extractors, operator guidance and rich speaker/date parsing retain the
original contract. Mixed roles, named speakers, contextual pronouns, relative
dates, obvious formatted transcripts/code and unvalidated multilingual inputs
also fall back. These exclusions deliberately limit coverage. Conversation
graph ingestion still uses its original cleaned episode; Graphiti's generative
entity/relationship extraction is not replaced by this sentence selector.

Existing storage, sensitivity regex gates, authorization, source metadata and
graph group boundaries remain in effect. Source offsets ground reconstruction
but are not persisted as a new provenance field. The rejected native Needle
prototype is not part of the runtime; Jev abstention goes directly to the
original extractor.

## Quality findings and limits

The benchmark calls the actual service extractor. Its handwritten rubric checks
category and required text fragments, rejects unmatched extra outputs and exact
duplicates. It is **not a calibrated semantic judge, atomicity score, or claim of
production precision/recall**. A legitimate alternate category or splitting a
qualified statement over two memories can fail this strict rubric.

Examples observed:

- Verbatim selection preserved the Python qualifier in a convention that Gemini
  sometimes generalized to all functions, and preserved negation/usage limits.
- On the held-out named-person example, baseline added an unsupported inference
  that the named person was the user; Jev selected the stated residence only.
- Jev rejected hypothetical adoption and uncertain technology claims that the
  baseline sometimes converted to decisions or task context.
- All three held-out hybrid failures used Gemini fallback and assigned
  `architecture` rather than the rubric's `tech_stack` to a qualified Redis
  statement. The qualifier survived: these are category mismatches, not three
  demonstrated factual hallucinations.
- Instructions masquerading as content and a relative-date command still
  produced questionable memories through fallback on development cases. The
  original extractor is a compatibility fallback, not a correctness oracle.

The development run informed routing-policy changes; do not treat it as held-out.
The second set was frozen after those changes and was not used to retune them.
The initial policy produced 47/60 passes, 860 ms median and $0.010580 cost; keeping
that result prevents hiding the importance of taxonomy design. A single rubric
correction accepted “without the use of emojis” as equivalent to “without emojis”.
Baseline outputs were rescored without rerunning, changing 39/60 to 42/60;
latency and cost stayed identical. Raw and rescored reports are retained.

### Multiple categories are a separate model change

Current facts have one `category: str`, with independent multi-valued `tags` and
`concepts`. Search accepts a category list to query several buckets; it does not
make a stored fact multi-category. This implementation preserves that contract.

Jev can support multi-label decisions through independent Noul questions batched
against the same evidence. A Choice's competing probabilities are not proof that
all high-ranked labels apply. A backward-compatible future design could retain
one primary category for scope/visibility/organization and add secondary
categories for retrieval on the same memory ID. It requires explicit storage,
index, API and security semantics, not duplicate copies of the same fact.
See [Choice](https://docs.typesafe.ai/primitives/choice) and
[Noul](https://docs.typesafe.ai/primitives/noul).

## Actual graph and vector paths

The graph harness now optionally calls `extract_facts_only` before storing every
primary input's resulting facts through real MemoryService, the Mem0 adapter,
Neo4j and Qdrant. Each arm has isolated namespaces. This is not a mocked vector
test. Baseline runs first, then hybrid extraction plus hybrid graph resolution,
then simulated missing Jev credentials to force original-model fallback.

| Three source writes | Baseline | Hybrid | Jev unavailable |
|---|---:|---:|---:|
| Acceptance checks | 21/21 | 21/21 | 21/21 |
| Median write time | 11.63 s | 9.09 s | 12.76 s |
| Slowest write | 17.33 s | 19.69 s | 18.24 s |
| Total time, three writes | 37.44 s | 37.03 s | 40.66 s |
| Listed generation cost | $0.005873 | $0.004349 | $0.005876 |

Hybrid cost was 26% lower, but total elapsed time improved only 1.1%, and the
slowest write was 14% slower. With three inputs, this is a functional/cost pilot,
not a reliable throughput or p95 estimate. Both extraction and graph resolution
changed, and generated fact counts differed, so savings cannot all be attributed
to the extractor alone. Extraction-only figures above isolate that component.

Checks cover persisted entities/edges, entity reuse, temporal invalidation of
old employment, current relationship retention, exact write idempotence,
graph-only/vector-only/combined recall, populated foreign tenant and project
isolation, graph endpoint groups and no cross-tenant invalidation. Embedding
latency is included but embedding cost is unpriced; API, queue and infrastructure
costs are excluded. Extra isolation-setup writes are recorded separately, not
included in the three-write cost. Public list rates are the same as report 28;
actual account credits and billing are not measured.

## Probability and latency follow-up

### Implemented, still opt-in

- Preserve the complete Jev Choice distribution, including `UNCERTAIN`, without
  another model call. `category_evidence` records probabilities, the provider's
  distribution-derived confidence, primary category, model, policy version and a
  source-content hash. These are competing relevance weights, **not independent
  confirmed memberships or calibrated factual confidence**.
- Persist evidence on the same Qdrant memory through conversation, ingest, raw
  and batch writes. Existing tuple extraction returns remain compatible via an
  optional output map. Responses expose the evidence; legacy records return null.
  Existing dedup survivors are not overwritten/backfilled. No duplicate vector
  memories or graph edges are created for secondary categories.
- Pass only probabilities/mode to the optional Jev reranker, after authorization.
  Primary-category filters remain exact; secondary scores do not silently widen
  a query. No category index migration or retrieval-quality improvement is claimed.
- Remove evidence on content/category edits; reads also reject evidence whose
  hash, primary category, policy version or distribution no longer validates.
- Separate telemetry into `retain_uncertain`, `standalone_uncertain` and
  `category_policy_uncertain`, retaining numeric head scores but no source text.
  Fact-safety acceptance remains at the existing threshold.

Uncertain category choices can be accepted as soft metadata only if the winning
category has at least 0.5 probability, the top three known categories carry at
least 0.95 mass, `UNCERTAIN` is at most 0.05, and **every nonzero known alternative
has the same scope class, default visibility and working-context lifetime class**.
These are conservative experimental routing bounds, not calibrated guarantees.
Any unsafe retention/standalone decision still falls back for the entire window.
Graph node/edge choice validation is unchanged; only source extraction requests
structurally valid low-confidence distributions from the shared adapter.

This distinction matters: `tech_stack` versus `architecture` can share storage
policy, whereas `preference` versus `convention` crosses private/shared and
global/project boundaries. Soft relevance must not become an access decision.

### Bounded work and warmup

API and worker startup warm the blank sentence tokenizer and reusable Jev HTTP
client locally. Warmup sends no requests or user data and spends no model tokens.
It does not pre-establish the provider's TLS connection or guarantee a warm remote
model. The legacy path stays untouched when the extraction flag is off.

`JEV_EXTRACTION_DEADLINE_S=2.5` bounds waiting for the Jev extraction operation,
including local segmentation. It is **not an end-to-end deadline** covering Gemini,
database writes or queue time. Four in-flight slots per process/credential/model
prevent an unbounded thread backlog; saturation immediately returns to the
original extractor. Three provider failures/timeouts open a 30-second circuit;
one half-open probe tests recovery. Semantic abstention does not open the circuit.

Python cannot cancel an already-running synchronous HTTP call. Late results may
still bill, but cannot publish facts or evidence. Their usage remains logged;
benchmark deadline snapshots mark cost as incomplete rather than zero. This is
bounded fallback waiting, not a claim that all provider work is cancelled.
Request logging context is propagated into the bounded worker. No speculative
Gemini hedging or relaxed graph invalidation was added.

### Fresh results

The larger comparison alternated baseline/hybrid order across repeats: 32
synthetic inputs × 2 repeats **per arm**, with local warmup outside request timing.
The corpus combines the previous development and held-out sets; it is not a new
unseen quality set. Provider calls, errors and fallback costs are recorded.

| Measure | Gemini baseline | Updated hybrid |
|---|---:|---:|
| Median extraction | 794 ms | 376 ms (53% lower) |
| p95 extraction | 964 ms | 1,205 ms (25% higher) |
| Listed API cost, 64 runs | $0.013029 | $0.006730 (48% lower) |
| Strict category/fragment rubric passes | 45/64 | 57/64 |
| Generative extraction calls | 64 | 19 |

Of the 19 hybrid fallbacks, ten were structurally unsupported inputs, four were
retention uncertainty, four were standalone uncertainty and one was category
policy uncertainty. **No accepted fact in this run used soft category acceptance.**
Therefore these results establish overall hybrid behavior, not a measured speedup
caused by soft categories. The retained scores are what let us identify the
remaining bottleneck accurately. The first Jev attempt took 2.13 seconds despite
local warmup, followed by Gemini; cold/provider effects are not eliminated.

At four concurrent calls, on the 12-input set × 3 repeats per arm:

| Measure | Gemini baseline | Updated hybrid |
|---|---:|---:|
| Median | 811 ms | 504 ms |
| p95 | 1,139 ms | 1,326 ms |
| Listed API cost | $0.007295 | $0.003527 |
| Strict rubric passes | 25/36 | 33/36 |

Concurrent arms ran in separate sequential processes to avoid racing global
settings; they were not interleaved. Nine hybrid requests fell back: three due to
unsupported source and six to standalone safety. Neither run had provider errors
or deadline/capacity fallbacks. These are small load pilots, not production SLAs.
Do not compare the old 1,449 ms p95 directly with the new 1,205 ms as a causal
optimization claim: corpus, ordering and conditions differ. P95 is still worse
than the matched Gemini baseline; further work is needed before a tail-latency
rollout claim. Lowering factual safeguards merely to improve that number is not
part of this implementation.

A separate six-input category-overlap probe, repeated twice, passed its broader
acceptable-category rubric on all 12 runs. Six responses qualified for soft
category handling but correctly fell back because standalone-fact safety was
below threshold. Two runs were accepted directly with certain categories; ten
used Gemini. No soft fact was ultimately stored. This reinforces that category
ambiguity and factual safety are separate bottlenecks, and does not demonstrate
a live speed benefit from soft acceptance. Its fixtures and results are recorded
in the private `extraction-v2-overlap.json` artifact.

### Graph/vector and safety verification

Fresh actual extraction-to-storage tests passed **26/26 baseline, 27/27 hybrid,
and 26/26 missing-key fallback checks**. The hybrid's extra check verifies live
extracted probability metadata round-trips. A separate deterministic soft-score
fixture checks real storage even when live responses happen to be confident:
weights persist, the record remains private, strict category filters do not
expand, the original fact is recalled from the graph, and a foreign graph group
cannot retrieve it. This fixture tests the storage contract, not Jev accuracy.

For the three primary source writes, baseline versus hybrid generation cost was
$0.005904 versus $0.004609 (22% lower); total elapsed time was 38.58 versus 37.12
seconds (4% lower). Slowest write was 17.74 versus 18.17 seconds. Again, only three
writes: functional acceptance and cost accounting, not a throughput estimate.
Embedding cost, infrastructure and queue latency remain excluded as before.

New contract tests cover policy-boundary refusal, malformed probability payloads,
fact-safety independence, whole-window evidence publication, raw/batch/ingest
round-trips, stale evidence after edits, unchanged permissions, reranker context,
bounded timeout/capacity, late results, circuit recovery and single recovery probes.

Final source verification after review cleanup: **2,731 passed, 14 skipped** on the host and **2,731
passed, 2 skipped** in the Docker test image. Both runs reported 29 warnings,
including short test JWT keys and unawaited mock coroutines. The final runtime
image also built successfully and passed imports, local tokenizer/client warmup,
and disabled-by-default extraction smoke checks. `git diff --check` passed.

### Future user-editable privacy policies (not implemented)

The existing baseline policy is deterministic category-default visibility plus
the sensitivity gate and explicit authorization rules. A future policy layer
could version user/project rules and compile them to bounded Jev questions for
semantic matching, with deterministic precedence and enforcement afterwards.
Explicit private decisions, hard sensitive-data rules and access controls must
not be overridden by a model's category scores. Ambiguous results should remain
private or require review; user-authored rules cannot grant permissions the
author lacks. Audit records should identify the policy version and matched rule.

Synthetic policies would be useful test fixtures, not silently activated sharing
rules. This change adds no policy editor, generated sharing rules, privacy model
calls, retroactive reclassification, or deployment changes.

## Maintainability and upstream-sync audit

The five new runtime modules total 672 lines including comments and whitespace:
one shared Jev transport/validation adapter (257), service wiring (116), source
selection (143), bounded execution (79), and category evidence (77). This is not
a minimal one-call substitution, but it
does not introduce a provider framework, replace vendor generation APIs, fork
the extraction pipeline, or build the deferred policy engine. Validation,
whole-window fallback and late-result isolation account for useful complexity.
The failed Needle experiment was removed from the runtime and dependency graph
after review rather than shipping an unisolated native path.

Existing subtree ancestry, package layouts and `scripts/sync-upstream.sh` are
unchanged. There are four modified vendor files and one added adapter:

| Local delta | Upstream maintenance obligation |
|---|---|
| Graphiti `node_operations._resolve_with_llm` | Preserve the optional decision hook, candidate-ID schema, and original-model fallback |
| Graphiti `edge_operations.resolve_extracted_edge` | Preserve the optional decision hook, duplicate/invalidation candidate distinction, and original temporal resolver |
| New Graphiti `llm_client/jev_client.py` | NS-owned implementation; verify context/response contracts when upstream changes them |
| Mem0 `graphs/configs.py` and `memory/graphiti_memory.py` | Additive configuration and wiring in NS's already-maintained graph layer; retain the opt-in defaults |

Upstream pulls remain possible, **not guaranteed conflict-free**. The two
Graphiti maintenance functions are upstream-owned conflict surfaces. The Mem0
graph-layer divergence predates this work; see the existing upstream delta
report. No vendor upgrade or trial merge of current upstream HEAD was performed
as part of this audit, so this is not a claim of compatibility with an untested
future release. After a sync, rerun the adapter/source-selection contracts, the
live graph isolation/invalidation/outage checks, and the container build gate.
